# 1．当前工程基准
## 1.1 项目定位
这是一个 **iOS 原生 SwiftUI 记账 App**，当前工程名已经统一为 **Ledger**。
核心设计思想：
- **本地优先**：本地单机即可完整使用
- **Apple 原生优先**：SwiftUI + PhotosUI + Vision + AuthenticationServices + CloudKit
- **无需自建后端**：不依赖自部署服务器
- **支持专题账本**：普通流水之外，还支持主题账本归集
- **支持 OCR 导入**：从支付截图识别金额、标题、支付渠道、时间、分类建议

# 2．全局导航与交互总原则
## 2.1 底部 Tab 结构
底部导航固定为 5 个 Tab：
1. 概览
2. 账本
3. 流水
4. 识图
5. 更多

“更多”内再进入：
- 预算
- 分类
- 设置

## 2.2 每个 Tab 要单独维护 NavigationStack
要求：
- 每个 Tab 都用自己独立的 `NavigationStack`
- 当用户重新点某个 Tab，应该尽量回到该 Tab 的最外层
- 当前项目通过 `Notification.Name.ledgerResetTabRoot` + reset token 完成

实现参考：
- `LedgerApp.swift`
- `RootTabView`
- 各页面中的 `.onReceive(NotificationCenter.default.publisher(for: .ledgerResetTabRoot))`

## 2.3 弹层类型使用规则
### 2.3A 保存退出提示（必须单独实现）
这是一个强制要求，不能省略。
凡是用户会编辑表单内容的页面，只要存在尚未保存的改动，在用户尝试离开当前页面时，都必须弹出“保存退出提示”。

适用页面至少包括：
- 新建账本
- 编辑账本（账本设置）
- 新建流水
- 编辑流水
- 未来若新增预算编辑、分类编辑、OCR 结果确认编辑页，也应复用同一套机制

触发时机包括：
1. 点击左上角"取消"
2. 用手势下拉关闭 sheet
3. 切换页面导致当前编辑页即将被销毁
4. 未来若改为 push 页面，则点击返回时同样要拦截

交互式要求：
- 不要直接丢数据
- 使用 `confirmationDialog` 或等价的原生确认交互
- 文案要明确说明"改动还未保存"

标准选项必须固定为：
- 保存
- 丢弃更改
- 继续编辑

标准行为：
- 选择"保存"：先执行保存逻辑，保存成功后再退出
- 选择"丢弃更改"：直接退出，不保存
- 选择"继续编辑"：关闭提示，留在当前页

实现建议：
- sheet 页面统一用 `SheetDismissGuard` 拦截手势关闭
- 表单页维护一个 `hasUnsavedChanges` / dirty state
- dirty state 建议基于"进入页面时快照 vs 当前表单状态"比较

这条规则要单独写给 AI，因为它不是 UI 装饰，而是防止误操作的数据保护功能。
必须严格区分：

### 用 `sheet`
适合：
- 新建/编辑表单
- 快速修改分类
- 快速修改账本归属
- 支付渠道选择器
- 自动归集开启确认面板
- 分享系统面板

### 用 `NavigationLink`
适合：
- 进入账本详情
- 进入分类层级选择下一层
- 进入账本归属选择页
- 进入自动归集分类选择页
- 进入设置二级内容

### 用 `alert`
适合：
- 删除确认
- 全局错误提示
- 明确的危险操作提醒

### 用 `confirmationDialog`
适合：
- 用户编辑中退出但尚未保存
- 需要给“保存 / 丢弃 / 继续编辑”三选一

### 用 `popover`
适合：
- 流水卡片上多个账本的简要小窗查看
- 小范围、轻量信息补充

# 3．数据模型约束（必须遵守）
## 3.1 LedgerBook（账本）
字段要点：
- `id`
- `name`
- `icon`
- `color`
- `note`
- `startDate`
- `endDate`
- `autoCollectEnabled`
- `budgetLimitAmount`
- `budgetStartDate`
- `budgetEndDate`
- `expenseAmount`
- `incomeAmount`
- `balance`
- `transactionCount`
- `participantNames`
- `isPinned`
- `autoCollectCategoryIds`

规则：
- `participantNames.count > 1` 视为多人分开账开启状态
- 账本预算与账本时间范围一致，不单独配置另一套时间交互
- `autoCollectCategoryIds` 为空时表示"全部分类都可自动归集"

## 3.2 LedgerTransaction（流水）
字段要点：
- `title`
- `amount`
- `kind`（收入 / 支出）
- `happenedAt`
- `categoryId`
- `categoryName`
- `merchant`
- `paymentMethod`
- `note`
- `source`（manual / ocr）
- `bookId`
- `bookName`
- `bookIds`
- `bookNames`
- `installmentGroupId`
- `installmentIndex`
- `installmentMonths`
- `installmentOriginalTotal`
- `paidByParticipantId`
- `paidByParticipantName`
- `splitParticipantIds`
- `splitParticipantNames`

规则：
- 一条流水**可以归属多个账本**，以 `bookIds/bookNames` 为准
- `bookId/bookName` 是"主账本"兼容字段，通常取 `bookIds.first`
- OCR 导入只是来源之一，不可跳过用户确认强制记账（单条导入时必须确认）
- 分期是存储层拆单，而不是仅 UI 标签

## 3.3 分类模型 LedgerCategory
必须支持：
- 多级树结构
- 父节点可直接选为类别
- 子节点也可选为类别
- 统计、筛选、自动归集都要支持"父节点包含所有后代"的匹配逻辑

# 4．账本模块：页面结构与交互规格
## 4.1 账本列表页（BooksView）
### 4.1.1 页面结构
列表页从上到下：
#### A．顶部汇总区
是一个 `Section`，包含 3 张统计卡：
- 账本数
- 主题支出
- 主题收入

展示形式：
- 横向 3 卡片
- 使用玻璃卡片风格 `glassCard`

#### B．搜索框
搜索框为**常驻显示**，不额外放放大镜按钮作为入口。
UI 结构：
- 左侧放大镜 icon
- 中间 `TextField("搜索账本标题")`
- 右侧当有文字时显示清空按钮

搜索范围：
- 账本名称
- 账本说明 `note`

#### C．账本卡片列表
每个账本卡片要展示：
- 图标（圆形背景）
- 名称
- 说明（可选）
- 是否置顶图标
- 笔数 tag
- 支出 tag
- 收入 tag（若 > 0）
- 净额
- 时间范围

### 4.1.2 排序规则
账本列表排序：
1. 先按 `isPinned`，置顶的在前
2. 再按 `startDate` 倒序
3. 再按 `id` 倒序

### 4.1.3 左滑 / 右滑动作
当前实现是 **trailing swipeActions**，包含：
- 置顶 / 取消置顶
- 删除

要求：
- 不允许全滑直接删除，`allowsFullSwipe: false`
- 删除必须再弹 `alert` 确认

### 4.1.4 工具栏按钮
右上角两个按钮：
- 刷新按钮：重新 `loadBooks()`
- 加号按钮：打开新建账本 `sheet`

### 4.1.5 空状态
当列表为空时：
- 用 `ContentUnavailableView`
- 文案区分：
  - 无搜索词：`暂无主题账本`
  - 有搜索词：`没有匹配的账本`

## 4.2 新建 / 编辑账本页（CreateBookView）
这是一个**表单 sheet**，不是 push 页面。
交互容器：
- `sheet`
- 内部自己包一层 `NavigationStack`
- 顶部按钮：取消 / 保存
- 未保存退出：`confirmationDialog`
- 开启自动归集额外确认：`sheet(AutoCollectSetupSheet)`

### 4.2.1 页面标题
- 新建时：`新建账本`
- 编辑时：`账本设置`

### 4.2.2 Section 划分
#### Section 1: 基础信息
包含：
1. `TextField("账本名称")`
2. 图标选择区
3. 颜色选择区
4. 说明文本框

##### 图标选择区要求
- 默认收起，不要一开始把全部 icon 铺满
- 顶部是一行预览条目：
  - 左侧当前图标预览
  - 中间标题"图标"
  - 下方显示 icon 名称或提示文案
  - 右侧 chevron 展开/收起
- 点开后才展示 `LazyVGrid` 图标库
- 图标库使用 `DisplayPalette.icons`

##### 颜色选择区要求
- 显示当前色块预览
- 使用 `DisplayPalette.colors`
- 颜色是直接点选，不允许要求用户手输 hex

##### 说明文案
当前有一条辅助文案：
- “上面两个分别是：账本显示图标和主题颜色。只影响界面展示，不影响记账逻辑。”
如果未来要做极简模式可删，但当前产品逻辑允许保留。

#### Section 2：时间范围
包含：
1. 开始时间 `DatePicker`
2. `Toggle("设置结束时间")`
3. 若开启，则展示结束时间 `DatePicker`
4. `Toggle("自动归集范围内流水")`
5. 若自动归集已开启，显示自动归集说明 + 自动归集分类入口

##### 时间规则
- `startDate` 必填
- `endDate` 可选
- 若无结束时间，则为开放区间

##### 自动归集开关规则
不能直接打开。
当用户第一次从关闭切到开启时：
- 不直接生效
- 先打开一个 **sheet 弹层**：`AutoCollectSetupSheet`

弹层内必须有：
- 标题：`开启自动归集`
- 一段说明文案，文案依赖设置页里“是否开启归属提示”
- 一个勾选开关：`保存后主动归集一次已有流水`
- 两个并排按钮：`取消` / `开启`

行为：
- 点取消：不启用自动归集
- 点开启：`autoCollectEnabled = true`
- 若勾选了“主动归集一次已有流水”，则保存账本后调用批量归集逻辑

#### Section 3：自动归集分类
仅在 `autoCollectEnabled == true` 时显示。

入口形式：
- `NavigationLink`
- 进入 `BookAutoCollectCategoryPickerView`

主页面这一行展示：
- 左边：`自动归集分类`
- 右边：
  - 未选任何分类：`全部分类`
  - 已选若干分类：拼接名称摘要

##### 分类选择规则
这是一个**push 页面**，不是 sheet。
页面内规则：
第一项固定是“全部分类”
- 点中后清空 `selectedCategoryIds`
- 下方展示支出分类
- 只做支出分类自动归集，不处理收入分类自动归集
- 若选中某父节点，则其子节点不再单独显示在可见列表中
- 若选择某分类时，它的后代和祖先都要互斥去重

也就是说：
- 选了父类，就不必再选子类
- 选了子类，再选父类时，子类应被清掉
- 这是为了避免重复匹配和 UI 混乱

#### Section 4：账本预算
包含：
- `Toggle("启用账本预算")`
- 若开启，则显示 `TextField("预算金额")`
- 下方提示：预算周期自动与账本时间一致

规则：
- 账本预算不再单独让用户设置另一套起止时间
- `budgetStartDate = startDate`
- `budgetEndDate = endDate`（若有）

#### Section 5：多人分账
包含：
- `Toggle("启用多人分账")`
- 若开启：
  - 新增成员输入框
  - 右侧加号按钮
  - 成员列表（每行可编辑名称 + 删除）
  - 一个“恢复默认成员（我）”按钮

规则：
- 默认关闭
- 默认成员初始值为 `["我"]`
- 开启后若没有有效成员，不允许保存
- 成员名称要去重、去空格、过滤空字符串

### 4.2.3 保存规则
点击右上角“保存”时：
- 组装 `BookDraft`
- 编辑模式：调用 `store.updateBook(id, with: draft)`
- 新建模式：调用 `store.createBook(draft)`
- 如果 `collectExistingNow == true`：
  - 再调用 `store.collectTransactionsIntoBook(targetBookId)`
- 成功后关闭 sheet

### 4.2.4 未保存退出 / 保存后再退出
这是很关键的交互，也是必须写进 AI 实现要求的内容。

要求：
- 用户点左上角“取消”时，如果有未保存修改，不允许直接关闭
- 用户下拉 sheet 尝试关闭时，如果有未保存修改，也不能直接关闭

实现方式：
- 用 `SheetDismissGuard`
- 用 `confirmationDialog("改动还未保存")`
选项必须是：
- 保存
- 丢弃更改
- 继续编辑

## 4.4 账本自动归集：业务规则
### 4.4.1 自动归集中条件
一笔流水中某账本自动归集，必须同时满足：
1. 该账本 `autoCollectEnabled == true`
2. 流水时间落在账本时间范围内
3. 若账本设置了 `autoCollectCategoryIds`，则流水分类必须命中该分类集合

### 4.4.2 分类命中规则
- 若账本未配置任何自动归集分类，则视为全部分类都可归集
- 若选择的是父节点，则其全部后代分类也算命中
- 这一点必须走路径前缀匹配，不可只做 id 相等

### 4.4.3 推荐与自动加入的区别
#### 情况 A：设置里开启了“新流水显示账本归属推荐”
则：
- 新建流水页中显示“符合这些账本时间范围 / 可补充关联到这些账本”的推荐区
- 由用户手动点“添加”
- 保存时不会再自动偷偷加入未选账本

#### 情况 B：设置里关闭了“新流水显示账本归属推荐”
则：
- 用户保存流水前不弹推荐
- 保存时系统把命中的自动归集账本直接加入 `draft.bookIds`

### 4.4.4 一条流水可归属多个账本
必须支持。
不能因为符合多个账本条件却只推荐一个。

实现上：
- `LedgerStore.resolveBooksForTransactionDraft(_:)` 返回数组
- 最终写入 `bookIds / bookNames`

### 4.4.5 批量归集已有流水
仅在用户开启自动归集时，由确认 sheet 的勾选决定是否执行。
不是账本列表里常驻按钮，不做单独“批量关联”入口。

# 5．流水模块：页面结构与交互规格
## 5.1 流水列表页（TransactionsView）
页面标题：`流水`

### 5.1.1 页面上方固定筛选区
通过 `.safeAreaInset(edge: .top)` 固定在列表上方。
内容从上到下：

#### A．流向筛选条
三项：
- 全部
- 支出
- 收入

- 胶囊按钮组
- 当前选中项填充高亮色

## 6.6A 设置页中的保存退出提示要求
当前设置页本身大部分是即时生效，因此不需要整页“保存”按钮。
但如果未来在"设置"内新增下列页面，请一律套用同一套"保存退出提示"机制：
- 独立的预算编辑页
- 独立的分类编辑页
- 独立的同步配置表单页
- 复杂 OCR 修正表单页

也就是说：
- 即时生效型设置：可以不弹保存退出提示
- 表单聚合型设置：必须支持"保存 / 丢弃 / 继续编辑"

这样可以避免后续扩展时，同一个 App 里出现两套完全不同的退出逻辑。

# 7．Store 层必须提供的方法与职责

- `updateBook(_:with:)`
- `deleteBook(_:)`
- `setBookPinned(_:pinned:)`
- `collectTransactionsIntoBook(_:)`
- `shouldAutoCollect(into:date:categoryId:)`
- `recommendedBooks(for:)`
- `matchesAutoCollectCategory(book:transactionCategoryId:)`

### 账本删除规则
删除账本时：
- 删掉账本本身
- 删掉名称关联的预算（当前实现如此）
- 遍历所有流水，移除该账本 id/name

### 编辑流水时的关键规则
- 编辑是单条更新，不重新拆分期组

- 更新账本数组、分类、支付渠道、分账信息

# 8．用户体验细节要求（必须遵守）
## 8.1 不要把所有可选项直接铺满页面
例如：
- 图标库默认折叠
- 分类树不要默认平铺在新增流水页
- 支付渠道用二级选择 sheet
- 自动归集分类用 push 页面

## 8.2 危险操作一定要二次确认
包括：
- 删除账本：`alert`
- 删除流水：`alert`
- 关闭未保存表单：`confirmationDialog`
- 开启自动归集：先 `sheet` 确认再保存

## 8.3 表单退出防丢失
以下页面都必须做未保存保护：
- 新建/编辑账本
- 新建/编辑流水

方式统一：
- 左上取消时检查 dirty
- 手勢下拉关闭时检查 dirty
- 用 `SheetDismissGuard`

## 8.4 一切“推荐”都做轻量展示，不做强打断弹窗
包括：
- 新流水推荐关联账本
- 编辑流水推荐补充关联账本

不能：
- 一进入页面就弹 modal 强制问

## 8.5 多账本显示要克制
不要在流水卡片上直接显示一长串账本名字。

正确做法：
- 卡片里只显示 `...` 小 tag
- 点击后 `popover` 看详情
